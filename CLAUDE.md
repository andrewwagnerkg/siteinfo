# CLAUDE.md — правила проекта для всех агентов

Это сайт IT-компании. Его разрабатывают, наполняют и публикуют агенты Claude Code.
Запросы пишет любой участник команды, который склонировал этот репозиторий.

Перед работой прочитай документы в `docs/`:
- `docs/tech-stack-decision.md` — стек, окружения, процесс, бюджет
- `docs/site-structure.md` — карта сайта, коллекции контента, требования
- `docs/agent-workflow-diagram.md` — схема процесса
- `docs/design-system.md` — дизайн-система (ведёт агент `designer`)

## Стек
- Astro + TypeScript, статическая сборка (`output: 'static'`)
- Контент — Markdown/MDX в `src/content/` (Astro Content Collections)
- Tailwind CSS, токены дизайна — в `src/styles/` и `docs/design-system.md`
- Локализация: Astro i18n. Языки: `en` (основной, без префикса), `ru` (`/ru/`), `ky` (`/ky/`)
- Тесты: Playwright (`tests/`)
- CI/CD: GitHub Actions (`.github/workflows/`)
- dev-стенд: GitHub Pages. prod: пока не настроен

## Команды
- `npm install` — установка зависимостей
- `npm run dev` — локальный сервер
- `npm run build` — сборка (должна проходить без ошибок и предупреждений)
- `npm run test` — тесты Playwright
- `npm run check` — проверка типов и контента (`astro check`)

Если репозиторий ещё пустой — сначала выполни раздел «Первый запуск» ниже.

## Команда агентов
| Агент | Файл | Зона ответственности |
|---|---|---|
| `developer` | `.claude/agents/developer.md` | Код: страницы, компоненты, маршруты, схемы коллекций, i18n |
| `designer` | `.claude/agents/designer.md` | Дизайн-система, стили, внешний вид компонентов |
| `content` | `.claude/agents/content.md` | Тексты, переводы, новости, вакансии, кейсы |
| `tester` | `.claude/agents/tester.md` | Сборка, тесты, проверка требований. Код не правит |
| `publisher` | `.claude/agents/publisher.md` | Ветки, коммиты, pull request, теги релизов |

## Как обрабатывать запрос участника
Ты (основная сессия) — координатор. Сам код не пишешь, а распределяешь работу между агентами.

1. Уточни запрос, если он неоднозначный. Коротко перескажи план участнику.
2. Попроси `publisher` создать ветку `feat/<короткое-имя>` (или `fix/…`, `content/…`) от свежего `development`.
3. Подключи нужных агентов по порядку. Не каждому запросу нужны все:
   - новая страница/функция: `developer` → `designer` → `content` → `tester`
   - только тексты (новость, вакансия, кейс): `content` → `tester`
   - только внешний вид: `designer` → `tester`
4. Если `tester` нашёл ошибки — передай отчёт агенту, в чьей зоне ошибка, затем снова `tester`. Не больше 3 кругов; дальше — остановись и опиши проблему участнику.
5. Когда тесты зелёные — `publisher` коммитит, пушит и открывает pull request.
6. Сообщи участнику: что сделано, ссылка на PR. Напомни, что PR должен одобрить другой участник.

### Релиз на prod
Запрос вида «опубликуй текущую версию на prod» → `publisher` ставит тег версии на текущий `development`.
Откат «опубликуй v1.1.0» → `publisher` запускает деплой существующего тега.
Пока prod не настроен — сообщи об этом и ничего не публикуй.

## Общие правила
- Никогда не коммить напрямую в `development`. Только ветка + pull request.
- Никогда не делай `git push --force` в общие ветки и не удаляй чужие ветки.
- Не добавляй секреты, ключи, токены в репозиторий. Секреты — только в GitHub Secrets.
- Не добавляй новые npm-зависимости без необходимости. Если добавляешь — объясни зачем в описании PR.
- **Адаптивный дизайн обязателен.** Любая страница и компонент корректно работают на телефоне, планшете, ноутбуке и большом мониторе (360–1920 px). Подход mobile first. Правила — в разделе «Адаптивность» `docs/design-system.md`. Работа без проверки на всех ширинах не считается готовой.
- Минимум клиентского JavaScript. Анимации — CSS, с поддержкой `prefers-reduced-motion`.
- Без тяжёлого 3D/WebGL.
- Каждая страница существует на трёх языках: en, ru, ky.
- Не называй клиентов в кейсах — только отрасль и размер компании.
- Пиши код, комментарии и имена файлов на английском. Документацию в `docs/` — на русском.
- Если меняешь архитектуру, стек или процесс — обнови соответствующий документ в `docs/`.

## Первый запуск (пустой репозиторий)
1. `developer`: создать проект Astro + TypeScript + Tailwind, настроить i18n (en без префикса, ru, ky), коллекции из `docs/site-structure.md`, базовый layout, переключатель языка, страницу 404.
2. `developer`: настроить `base` и `site` для GitHub Pages через переменные окружения (для prod будут другие значения).
3. `developer`: добавить `.github/workflows/ci.yml` (сборка + тесты на каждый PR) и `deploy-dev.yml` (деплой на GitHub Pages после слияния в `development`).
4. `designer`: заполнить `docs/design-system.md` и токены в Tailwind (нейтральная палитра, пока нет брендбука).
5. `content`: заглушки для всех разделов на трёх языках.
6. `tester`: Playwright с проверками из раздела «Технические требования» в `docs/site-structure.md`.
7. `publisher`: ветка `feat/bootstrap`, PR.
