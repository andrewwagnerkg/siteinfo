# Структура сайта и тренды

Дата: 2026-11-19
Статус: принято (версия 1)

## Решения
- **Языки:** английский (основной), русский, кыргызский.
- **Услуги:** страница нужна; пока наполняется текстом-заглушкой, реальные услуги — позже.
- **Клиенты в кейсах:** не называем. Указываем только отрасль и размер компании («Финтех-стартап, 50 сотрудников»).
- **Блог:** пока нет. Статьи при необходимости публикуются как новости с тегом `article`. Если статей станет много — выделим отдельную коллекцию `blog`.
- **Кыргызские тексты** проверяет носитель языка (найдёт владелец проекта).

## 1. Что сейчас в тренде (исследование, ноябрь 2026)

Что берём:
- **Ясность для B2B важнее «вау-эффекта».** Сайт сначала понятно объясняет, что компания делает, и только потом впечатляет. Доказательства (цифры, реальные лица, кейсы) стоят рядом с утверждениями. (Digidop, Naturaily)
- **Сдержанная анимация.** Анимация направляет внимание (появление секций, состояния кнопок), а не развлекает. Обязательно уважать системную настройку «уменьшить движение». Предпочтительно встроенные средства браузера (CSS, View Transitions) вместо тяжёлого JS. (Digidop, Naturaily)
- **Один световой/материальный эффект на страницу** (свечение, «стекло») — только на главном элементе. (Digidop)
- **Компонентный подход и дизайн-система.** Когда страницы дёшево создавать (а у нас их создают агенты), единая дизайн-система и арт-дирекция становятся главными. (Digidop, Naturaily)
- **Скорость и доступность — обязательные требования**, а не опция. (Naturaily)
- **Структурированный контент для людей, поиска и AI-поиска:** понятные заголовки, прямые ответы, разметка Schema.org. (Naturaily)
- **Немного «человеческой фактуры»** — реальные фото команды, живые формулировки — чтобы не выглядеть как типовой AI-сайт. (Naturaily)

Что НЕ берём сейчас:
- Тяжёлый 3D/WebGL и сложный scrollytelling — бьёт по скорости на мобильных, сложно поддерживать агентам.

## 2. Языки и адреса

| Язык | Код | Адрес |
|---|---|---|
| English (основной) | `en` | `/` (без префикса) |
| Русский | `ru` | `/ru/` |
| Кыргызча | `ky` | `/ky/` |

- Переключатель языка на каждой странице ведёт на ту же страницу на другом языке.
- Сначала контент пишется на английском, затем агент `content` переводит на ru и ky.
- Кыргызский перевод помечается `needs_native_review: true` до проверки носителем языка.
- Если перевода страницы нет — тест падает.

## 3. Карта сайта

`{lang}` — пусто для en, `ru/` или `ky/` для остальных.

```
/{lang}                       Главная
/{lang}services/              Услуги (список, пока заглушки)
/{lang}services/{slug}/       Страница услуги
/{lang}portfolio/             Портфолио (кейсы, с фильтрами)
/{lang}portfolio/{slug}/      Кейс
/{lang}news/                  Новости (включая статьи с тегом article)
/{lang}news/{slug}/           Новость
/{lang}careers/               Вакансии
/{lang}careers/{slug}/        Вакансия
/{lang}about/                 О компании / команда
/{lang}contacts/              Контакты + форма заявки
/{lang}{slug}/                Произвольная страница (добавляется по запросу)
/{lang}privacy/               Политика конфиденциальности
/404                          Страница не найдена
```

Произвольные страницы: файл в `src/content/pages/{lang}/{slug}.md` — агенты добавляют/удаляют их как в CMS.

## 4. Типы контента (коллекции Astro)

| Коллекция | Поля |
|---|---|
| `projects` (кейсы) | title, industry, company_size, services[], year, cover, headline_metric, summary, quote {text, role}, published |
| `news` | title, date, cover, summary, tags[] (в т.ч. `article`), published |
| `careers` (вакансии) | title, level, location / remote, employment, stack[], open (true/false), apply_contact |
| `services` | title, icon, summary, related_projects[], placeholder |
| `team` | name, role, photo, links |
| `pages` | title, description, body, show_in_menu, order |

Общие поля для всех коллекций: `placeholder` (текст-заглушка), `needs_native_review` (для ky).
Каждый файл существует в версии на каждый язык (en, ru, ky).

## 5. Главная страница (сверху вниз)

1. **Первый экран:** одна фраза — что делаем и для кого + кнопка «Обсудить проект».
2. **Услуги:** 3–6 карточек (пока заглушки), каждая ведёт на страницу услуги.
3. **Избранные кейсы:** 3 карточки с ключевой цифрой результата.
4. **Цифры о компании:** лет на рынке, проектов, специалистов.
5. **Как мы работаем:** 4–5 шагов процесса.
6. **Отзыв клиента** (если есть; подпись — должность и отрасль).
7. **Последние новости:** 3 карточки.
8. **Мы нанимаем:** блок со ссылкой на вакансии (только если есть открытые).
9. **Финальный призыв:** форма или кнопка «Связаться».

## 6. Шаблон кейса

1. Контекст клиента: отрасль, размер, исходная ситуация (без названия компании).
2. Задача — словами клиента.
3. Что сделали — конкретно (стек, сроки, команда).
4. Результат — в цифрах, главная метрика первой.
5. Цитата клиента с должностью — сразу после результата.
6. Призыв в конце: «Обсудим ваш проект?».

Страница портфолио: фильтры по отрасли и услуге; карточка = отрасль + одна строка о результате + ключевая цифра; лучше 8–12 сильных кейсов, чем много слабых. Кейсы открыты, без форм и PDF.

Анонимные кейсы вызывают меньше доверия — компенсируем конкретикой: точные цифры, стек, сроки.

## 7. Технические требования (для тестировщика)

- **Адаптивный дизайн:** корректная работа на 360–1920 px (телефон, планшет, ноутбук, большой монитор), без горизонтальной прокрутки, с мобильным меню. Подробно — `docs/design-system.md`, раздел «Адаптивность».
- Lighthouse: производительность и доступность ≥ 90 на мобильных.
- Уважение `prefers-reduced-motion`.
- Контраст текста по WCAG AA, работа с клавиатуры.
- `sitemap.xml`, `robots.txt`, `hreflang` для en/ru/ky, Open Graph-картинки.
- Разметка Schema.org: Organization, Article (новости), JobPosting (вакансии).
- Все внутренние ссылки рабочие, у каждой страницы есть версии на всех трёх языках.
