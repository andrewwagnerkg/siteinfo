# Решение по технологическому стеку

Дата: 2026-11-19
Статус: принято (версия 3 — dev-стенд, релизы по тегам)

## Контекст
- Сайт IT-компании: портфолио проектов, новости, открытые вакансии, контакты для потенциальных клиентов.
- Нужна локализация: английский (основной), русский, кыргызский.
- Нужна возможность добавлять и удалять страницы (как в CMS).
- Разработку, поддержку и наполнение выполняют агенты Claude (Claude Code).
- **Владельцев много**: любой участник команды, который склонировал репозиторий, может писать запросы агентам.
- **Всё хранится в репозитории**: агенты, правила, ТЗ и документация — чтобы новый участник после `git clone` сразу мог работать.
- Бюджет на хостинг и сервисы: не более $1 в месяц.
- Посещаемость: до 100 посетителей в месяц.
- Жёсткого дедлайна нет.
- Домена пока нет. Дизайна и логотипа пока нет (будут позже). Ориентир — современные сайты IT-компаний.

## Окружения
| Окружение | Где | Когда обновляется |
|---|---|---|
| **dev** (демо-стенд) | GitHub Pages | Автоматически после каждого слияния в `main` |
| **prod** | Отдельный хостинг с доменом — **решим позже** (свой сервер или Cloudflare Pages) | Только по запросу участника, через тег релиза |

Пока prod не настроен, используется только GitHub Pages.

Замечание: GitHub Pages бесплатен для публичного репозитория; для приватного нужен платный план GitHub.

## Решение
Статический сайт, весь контент хранится в Git.

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | Astro (JavaScript/TypeScript) | Быстрый статический сайт, встроенная i18n-маршрутизация, контент-коллекции |
| Контент | Markdown/MDX-файлы в репозитории | Новая страница/новость/вакансия/кейс = новый файл; агентам удобно читать и менять |
| Стили | Tailwind CSS + описанная дизайн-система | Единые правила, которые агенты не нарушают |
| Локализация | Astro i18n (en — `/`, ru — `/ru/`, ky — `/ky/`) | Встроено, без внешних сервисов |
| Форма связи | Бесплатный сервис форм или отправка в Telegram | Не нужен свой сервер |
| Тесты | Playwright (ссылки, формы, мобильная версия), проверка сборки | Автоматическая проверка агентом-тестировщиком |
| CI/CD | GitHub Actions | Тесты на каждый PR, автодеплой dev после слияния в `main`, деплой prod по тегу |
| Хостинг dev | GitHub Pages | $0 |
| Хостинг prod | Решим позже | — |
| Админка | Пока нет | Контентом занимаются агенты. При необходимости позже — Git-CMS (Decap CMS или Keystatic) без переделки сайта |

### Почему не WordPress
Нужен сервер с PHP и MySQL (расходы, обновления безопасности), агентам сложнее работать с контентом в базе данных, не укладывается в бюджет $1/мес.

## Структура репозитория
```
/
├── CLAUDE.md              # общие правила для всех агентов: стек, стиль кода, процесс, запреты
├── README.md              # как начать: клонировать, установить, написать первый запрос
├── .claude/
│   ├── agents/            # описания агентов (по файлу на роль)
│   │   ├── developer.md
│   │   ├── designer.md
│   │   ├── content.md
│   │   ├── tester.md
│   │   └── publisher.md
│   └── settings.json      # общие настройки и разрешения Claude Code для проекта
├── docs/                  # ТЗ, решения, схемы
├── src/                   # код сайта (Astro)
├── src/content/           # контент: новости, вакансии, кейсы, страницы — по языкам
├── tests/                 # тесты Playwright
└── .github/workflows/     # CI: тесты, деплой dev, деплой prod
```

Личные настройки участника (например, `.claude/settings.local.json`) и секреты в репозиторий не попадают. Ключи доступа к prod-серверу хранятся только в GitHub Secrets.

## Команда агентов (Claude Code)
- **Программист** (`developer`) — создаёт страницы, компоненты, связи между страницами.
- **Дизайнер** (`designer`) — ведёт и соблюдает дизайн-систему.
- **Тестировщик** (`tester`) — запускает автотесты, проверяет результат.
- **Контент/SMM** (`content`) — пишет и переводит тексты, добавляет новости, вакансии, кейсы.
- **Публикатор** (`publisher`) — открывает pull request; по запросу на релиз ставит тег версии. Сам на сервер ничего не загружает — это делает GitHub Actions.

## Процесс разработки (dev)
1. Любой участник клонирует репозиторий и пишет запрос агентам.
2. Агенты работают в отдельной ветке участника.
3. Программист и дизайнер вносят изменения, Контент/SMM наполняет страницу на всех языках.
4. Тестировщик проверяет; при ошибках — возврат программисту.
5. Публикатор открывает pull request; GitHub Actions прогоняет тесты.
6. **Одобрить PR может любой участник, кроме автора.**
7. После слияния в `main` GitHub Actions автоматически обновляет dev-стенд на GitHub Pages.

Правила для `main`: прямые коммиты запрещены, только через PR с зелёными тестами и одним одобрением.

## Процесс релиза (prod)
1. Команда смотрит dev-стенд, версия всех устраивает.
2. **Любой участник** просит: «опубликуй текущую версию на prod».
3. Публикатор ставит на текущий коммит `main` тег версии (например, `v1.2.0`) и пушит его.
4. GitHub Actions по тегу собирает сайт с настройками prod (домен, корневой путь) и загружает на prod-хостинг.
5. Откат: «опубликуй `v1.1.0`» — GitHub Actions пересобирает и выкладывает старый тег.

Почему тег, а не ветка: тег навсегда указывает на один коммит, видно, что сейчас на prod, и легко откатиться. Ветка `release/...` создаётся только для срочного исправления prod, когда в `main` есть незавершённая работа.

Почему сборка отдельно для каждого окружения: GitHub Pages отдаёт сайт по пути `/<repo>/`, prod — с корня домена. Код один (тот же коммит), различаются только настройки сборки.

## Бюджет
- Хостинг dev: $0.
- Prod: решим позже (отдельный сервер, скорее всего, дороже $1/мес; Cloudflare Pages — $0).
- Домен: ~$10–15 в год (~$1/мес).
- Claude Code: каждому участнику, который пишет запросы, нужна своя платная подписка Claude.

## Открытые вопросы
- Prod-хостинг: свой сервер или Cloudflare Pages.
- Выбор домена.
- Интеграции (CRM, аналитика, Telegram).
- Чат/чатбот на сайте — пока не нужен.
- Дизайн, логотип, фирменные цвета — будут предоставлены позже.
